# 精度标签 → 地图解释：完整计划

日期：2026-09  
状态：P0 / P1 / P2 已实现  
对应能力：点「确定 / 约略 / 争议」精度标签，地图强调对应画法并展开说明

---

## 1. 目标

让公众通过一次点击，理解：

1. 地图上实线 / 走廊 / 虚线分别是什么意思；
2. 为什么这样画（史料范围、候选并列，而非「随便画的」）；
3. 依据从哪里来（段级 reasoning + 来源条数）。

红线：不伪装逐日 GPS；争议段不预设唯一正确答案。

---

## 2. 现状基线（实现前）

| 层 | 已有 | 缺口 |
|---|---|---|
| `node.precision` | confirmed / approximate / disputed | 只当静态 chip |
| `segments[].certainty` | 同三档 + reasoning + sourceIds | 证据栏有卡，点 chip 不联动地图 |
| 地图画法 | 走廊半透明、中心线、争议紫虚线 | 常显，无「聚焦某一类」 |
| `learningEmphasis` | route / terrain / evidence | 无 precision 强调档 |
| 文案 | BottomPanel `CERT_HINT`、EvidenceRail reasoning | 分散、重复 |
| 场景标注 | approximate 虚线框样式 | 与 chip 无闭环 |

## 3. 全量可优化清单

### 3.1 交互闭环

- 统一入口：节点 chip、账簿列表精度、证据栏 cert-chip、底栏当前段 cert、故事卡点位精度、图例
- 点选行为：toggle 再点取消；切节点/模式清除；与 `learningEmphasis` 的互斥规则
- 地图响应：
  - **确定**：实线加粗、走廊压暗
  - **约略**：走廊加宽加亮、中心线变细
  - **争议**：候选虚线抬升、非争议压暗
- 解释卡：一句定义 + 段级 `reasoning` + 来源数 +「不是逐日 GPS」
- 段级 vs 节点级：节点 chip → 相关出入段；底栏 chip → 当前 `activeSegment`
- 争议段特化：`seg-04`/`seg-08` 的 a/b 候选可逐条读来源

### 3.2 视觉编码（docs/15）

- 三档图元：实线实心 / 半透明走廊 / 紫灰双虚线，必须带文字
- 强调态与常态差异；禁止闪烁发光
- 红/紫/soft-red 色纪律
- 场景标注随对应精度强调一起亮

### 3.3 文案与信息设计

- 三档统一定义，一处导出、各处复用
- 解释卡层级：标题 → 你看到什么 → 为什么这样画 → 依据 N 条 → 免责
- 节点用「定位/点位」，路段用「走向/走廊」
- 「点位可确认但走向有分歧」要能说清

### 3.4 数据与模型

- `precisionExplain(kind, { node?, segments? })`
- 候选线元数据补全（label、sourceIds）
- `node.precision` 与出入段 `certainty` 一致性检查

### 3.5 学习模式 / 时间轴 / URL

- 扩展 `learningEmphasis` 或独立 `precisionEmphasis` 状态
- 播放/巡航：底栏 cert 随段变化；（可选）争议段自动停靠
- 深链接 `#p=disputed`
- 故事卡精度强调点位而非整段

### 3.6 无障碍与键盘

- chip 为 `<button aria-pressed>`
- Esc 层级兼容
- `aria-live` 播报强调状态
- 触控 ≥44px

### 3.7 移动与投影

- 手机解释卡改底部 sheet
- 投影模式线宽再抬一档

### 3.8 性能

- 只 `setPaintProperty`，不重建 style
- 与 `revealT` 显影叠加规则明确（先 reveal 再 emphasis）

### 3.9 测试与验收

- 三档文案、段线映射、paint stub、UI 接线静态测
- 验收：湘江（约略）→ 走廊亮；遵义～赤水（争议）→ 双虚线 + 解释 + 来源

### 3.10 内容债

- 争议段补「分歧是什么」短文
- 约略段固定角标「不代表逐日精确轨迹」
- 台账 `route-segment-register.csv` 与 UI `reasoning` 同源
