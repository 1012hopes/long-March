# 节点地图场景与渐进地形设计

日期：2026-09-03

## 目标

节点学习打开后，左侧不再只是放大的空地图，而是一张围绕当前历史问题组织的“节点地图场景”。地图必须在不依赖网络高程瓦片的情况下立即显示山脊、河谷、水系、当前路线和关键地点；在线 DEM 成功后，再渐进增强为真正的 3D 地形。

## 已确认问题

- `app/scripts/build-terrain.mjs` 已生成 `terrain-tint.png` 与 `hillshade.png`，但 `app/src/map/style.ts` 未将它们接入地图。
- 基础样式直接声明两个 AWS `raster-dem` 数据源，地形设色、阴影和真 3D 都会依赖网络。
- 当前山体阴影强度为 `0.1`，难以形成明显山河层次。
- 三份全局等高线 GeoJSON 超过 8MB，并在基础样式中声明，增加首屏解析负担。
- 节点学习模式隐藏次级地点、故事和地理标签，却没有替换为节点专属的路线、河流、渡口和山地说明。
- 右侧内容仍是窄单栏，未充分使用现有 `deep`、`fiveQuestions`、`stories` 与 `sources` 数据。

## 设计决定

采用“离线 2.5D 立即显示 + 节点地图场景 + 在线真 3D 渐进增强”。

### 第一层：离线 2.5D

- 基础地图只使用本地高程设色图、本地山体阴影、路线、水系和必要地名。
- 无网络时仍能看到完整的山河层次。
- 本地阴影是默认视觉，不需要用户点击“3D 地形”。

### 第二层：节点地图场景

每个节点拥有独立的地图场景配置：取景范围、重点路线段、上下文路线段、相关山河、渡口/会议/转向标注和地形表现类型。标注只使用现有来源可支持的地点与解释，不虚构精确坐标。

### 第三层：在线真 3D

- 节点地图完成首屏后，后台请求当前视口的 DEM。
- 3D 按钮显示 `未加载 / 加载中 / 已就绪 / 离线` 状态。
- DEM 就绪后才能抬升地形；失败时保持本地 2.5D，不出现空白和阻断提示。

## 节点学习版式

- 地图侧保留约 45%，内容侧约 55%。
- 地图侧增加节点地图展签，显示当前地点、日期、精度和地图阅读提示。
- 当前路线使用路线红，前后上下文路线降为低对比纸墨色。
- 关键河流使用证据蓝，渡口、转向和山地使用不同语义符号。
- 右侧桌面版采用主叙事 + 证据侧栏；手机保持单栏抽屉。
- 证据侧栏复用深度内容标签、相关故事和史料数量，不新增未经审核的历史正文。

## 性能策略

1. 首屏：本地地形图、主水系、当前路线与节点。
2. 地图可交互后：主要等高线与节点标注。
3. 节点放大或空闲时：局部细等高线。
4. 最后：当前视口在线 DEM 与真 3D。

## 视觉原则

- 山体阴影要明显，但不能变成卫星图或游戏地图。
- 河流必须参与解释路线，而不只是装饰背景。
- 任意节点地图最多一个主路线焦点、两个次级地理焦点。
- 标注使用地图展签、引线和方向箭头，不使用大量漂浮卡片。
- 所有视觉迭代必须通过 90 分截图门槛。

## 降级原则

- 本地高程图缺失：显示纸面底图、水系和路线。
- 在线 DEM 失败：3D 状态显示“离线”，不影响节点学习。
- 局部等高线未加载：保留高程设色和阴影。
- 减少动态：相机、地形抬升和路线强调立即切换。
